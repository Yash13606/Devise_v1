# Trusted local API extension contract

Current policy inspection additionally accepts optional `data_class: credentials|email`. Fixed bounded heuristics inspect string argument values and declared credential fields; they identify candidate patterns, not verified secret ownership or universal PII. Both a class and a literal condition require both matches. Redact needs a class or a nonempty literal; only matching spans/credential field values are replaced. Quoted-value boundaries and Unicode-fold spans preserve unrelated text. Decision audit metadata records reason, class names and matching policy IDs, never matched values. No user-supplied regex or hosted classifier is used.

`api.index.create_app(settings=None)` constructs the FastAPI app. Immutable `api.config.Settings` reads environment by default. Runtime `DATABASE_URL` uses `devise_app` (non-superuser, NOBYPASSRLS); separate `DATABASE_ADMIN_URL` targets the same database for `python -m api.manage migrate` / `seed-local`. Optional `--config .local/database.json` reads `runtime_dsn`/`admin_dsn`. Seed requires development/local configuration and a generated secret >=32 characters. The launcher injects environment; API never reads private DSN files implicitly.

Core routes match `LOCAL_IMPLEMENTATION_PLAN.md`. Seed accounts: `admin@local.devise.test` and `viewer@local.devise.test` belong to Local Alpha; `other@local.devise.test` administers Local Beta. Email login is a development harness: explicit `APP_ENV=development`, `DEVISE_AUTH_MODE=local`, secret, loopback client/Host, absent or exact allowed Vite Origin. Sessions have HS256 human-only audience, random ID and 30-minute expiry. Auth0 uses RS256 signature, exact issuer/audience, expiry/subject checks and server memberships. Enrollment/device secrets are random and stored as SHA256 hashes only.

Extensions use `api.auth.require_human(request) -> Identity(subject,email,name)`, `require_member(request, admin=False) -> Membership(org_id,role,subject)`, or `require_device(request) -> DeviceIdentity(device_id,org_id)`. Membership validates `X-Organization-ID` and resolves role from PostgreSQL. JWT claims, payloads and arbitrary headers confer no tenant/role authority.

`api.db.connection(settings, org_id=None, subject=None, device_token_hash=None, enrollment_hash=None, local_email=None)` yields a Psycopg3 dict-row connection in a single transaction, committed before success and rolled back on errors. Settings are transaction-local. Use parameterized SQL/`Jsonb`, explicit org_id inserts and composite tenant foreign keys. Register routers in `create_app`. Versioned `api/migrations/*.sql` run once under advisory lock. Grant required operations only to `devise_app`, revoke PUBLIC, enable/force RLS (`app.org_id` tenant scope; `app.subject` identity scope).

Bodies <=512KiB; event batches 1-100 strict metadata-only events, aware timestamps, confidence 0-1. Lists limit <=1000/offset <=1000000. Conflicting event IDs roll back whole batch (409); identical same-device retries count duplicates. Device lock serializes ingestion/revocation. Heartbeat persists actual monitoring/consent metadata; response `{config_version,config}` defaults `poll_interval_seconds:30`, `heartbeat_interval_seconds:30`, `monitoring_enabled:true`, `batch_size:100`, `observation_only:true`, `terminate_processes:false`, `clipboard_enabled:false`. Agent still requires explicit local consent.

Legacy `/api/event` and unrestricted scanner routes return 501. `/health` returns 503 for missing config, DB/schema outage or runtime role bypassing RLS. No automatic demo fallback.

## Supported governance HTTP JSON-RPC adapter

- `GET /api/policies` -> `{version,policies}`. `POST /api/policies` admin `{name,tool_name?,action?,text_pattern?,data_class?:credentials|email,outcome:allow|block|warn|redact|review,replacement?:"[REDACTED]"}` -> rule with id/version. `DELETE /api/policies/{id}` disables and advances tenant version. At most 200 active rules. `action` matches exact RPC method, `tool_name` exact tool name; text patterns are bounded case-insensitive literals, not regular expressions. Restrictiveness order: block, review, warn, redact, allow. No matching rule means block; explicitly configure an allow rule to permit a workflow.
- `POST /api/mcp/execute` human admin/member `{request_id:UUID,rpc:{jsonrpc:"2.0",id:string|integer,method,params}}` -> `{execution_id,decision,status,policy_version,result?,review_id?,continuation_token?,expires_at?}`. RPC methods: `initialize`, `ping`, `tools/list`, `tools/call`, `notifications/initialized`; JSON only, no SSE, subprocess, arbitrary URLs or sessions. `tools/call` params contain bounded `name` and object `arguments`. Unknown fields/methods, nesting >12 and oversized request bodies are rejected. `request_id` is the durable org-scoped idempotency ID and binds the exact RPC hash and subject. Retry of completed requests returns the stored encrypted result; executing attempts fail409 rather than dispatch twice.
- The single exact upstream URL comes from server `DEVISE_MCP_UPSTREAM_URL`, currently limited to an IP loopback HTTP URL with explicit port and exact `/mcp` path. Caller URL overrides, credentials, query strings, DNS aliases and redirects are not accepted. Caller bearer tokens are never sent upstream. `scripts/mcp_fixture.py` is a test fixture, not a production integration. Responses capped512KiB; connect timeout2s/read timeout5s. Timeout is `status:unknown`, other upstream errors `failed`; neither is automatically retried with the same request ID.
- Warning response issues a random continuation token once. `POST /api/mcp/continue {continuation_token}` requires the same subject/org and unchanged policy version. `GET /api/reviews -> {reviews}`; `POST /api/reviews/{review_id}/approve` or `/reject` administrator only. Approval dispatches the encrypted stored request once. Tokens/reviews bind request, policy and10-minute expiry; replay409, expiry410, changed policy409. Policy edits require a fresh evaluation. Matching redaction rules transform literal spans in argument string values before any approval or dispatch.
- Intent commits before dispatch, result commits separately. Concurrency claims prevent replay; a crash after upstream dispatch can leave `executing`/unknown outcome, which is deliberately not retried. This provides at-most-one dispatch per request ID, not distributed exactly-once guarantees for arbitrary external services.
- Pending requests and saved results use Fernet encryption. Local development derives its key from the generated local auth secret; production requires `DEVISE_PENDING_SECRET` >=32 characters. Raw pending content is removed after dispatch/rejection and access-time expiration. `python -m api.manage expire-pending` is the operator sweep for physically clearing encrypted content of idle tenants after the10-minute access TTL. This short development TTL awaits owner approval for hosted operation. Persisted result content is encrypted and requires separate retention decisions; general audit/log records contain no argument/result content.
- `GET /api/audit?limit=200&before_sequence=N` -> `{entries:[{sequence,kind,metadata,created_at,previous_hash,entry_hash}],has_more,next_before_sequence,order:"descending",chain_scope:"partial_window"}`. Limit is 1..1000. Without a cursor this returns the latest window, newest first; the optional positive bigint cursor is exclusive (`sequence < N`). `next_before_sequence` is the oldest returned sequence when older records exist, otherwise null. Continue with this cursor to read older history without repeats as new records arrive. Omit it again to see the latest records; the UI polls only this latest view every five seconds and offers Older records / Latest records controls. Original sequence/hash/payload fields are never rewritten. Each page is partial chain evidence, not independently verified complete history: reverse and concatenate all pages in sequence order to check links from the genesis hash, or use the bounded complete ascending metadata export. Concurrent appends require refreshing the latest window to include newer records. Appends serialize per org with a PostgreSQL advisory transaction lock and SHA256 canonical JSON chain. This is tamper evidence, not an immutable ledger. Helper `api.execution.append_audit(conn,org_id,kind,metadata)` requires a tenant-scoped connection; include actor subject in metadata where appropriate.

Integration tests use only `DATABASE_TEST_URL`/`DATABASE_ADMIN_TEST_URL` or ignored `database.json` `test_runtime_dsn`/`test_admin_dsn`; both must target `devise_test`. Tests never use application `devise_local` DSNs. The three local seed accounts are reusable fixture identities; test metadata remains synthetic.
